Privacy policy

ytpipe. Last updated 10 September 2026.

Who this covers

ytpipe is a personal command-line tool operated by one individual for their own YouTube channels. It has no other users. The only Google Account it accesses is the operator's own, authorised by that person through Google's standard OAuth consent flow.

YouTube API Services

ytpipe uses YouTube API Services (the YouTube Data API and the YouTube Analytics API). By using it, the operator agrees to be bound by the YouTube Terms of Service. Google's handling of the data that flows through those services is described in the Google Privacy Policy.

The authorised Google data ytpipe accesses is listed below. It is stored only on the operator's own computer and is never used to train any model. One narrow category leaves the computer, and it is described exactly under What is shared.

What is accessed

  • Channel identity and settings for channels the operator owns.
  • Publicly available YouTube search results and video statistics.
  • Video upload and metadata management on the operator's own channels.
  • YouTube Analytics for the operator's own channels.

Where it is stored

All data stays on the operator's own computer. OAuth tokens are written to a permission-restricted local directory. Job records, drafts and generated files are held in a local database and local folders. Nothing is uploaded to any server operated by ytpipe, because no such server exists.

What is shared

Nothing is sold or rented, and nothing is shared with anyone other than the services the tool calls in order to do its job. Those services are Google's YouTube APIs, and the AI providers named below, which are used to draft text and to synthesise narration: Anthropic, OpenAI and Google (Gemini). Their handling of what they receive is governed by their own terms.

Exactly one kind of YouTube data is sent to an AI provider. Before a script is written, ytpipe asks a language model to choose an angle that videos already on YouTube do not cover, and to do that it sends the titles of public videos returned by a YouTube search, together with three aggregate figures: how many results there were, their median view count, and their median duration. Those are public videos, not anyone's private data.

Nothing else from the YouTube APIs is sent anywhere: not the operator's channel identity or settings, not their videos' analytics, not their OAuth tokens, and nothing belonging to any other person. The operator is the only user of this tool and is the person whose credentials retrieved the data. No Google user data is used to train any model.

Retention and deletion

Data retrieved from the YouTube APIs is deleted automatically after 30 calendar days. ytpipe does this itself, on every run: the record of public videos found by a search is deleted, and the video titles kept alongside a draft are removed from it. The aggregate view and duration figures are kept, which the YouTube API Services Developer Policies permit for statistics (section III.E.4.b). The operator's own analytics are kept under the same section, and every run refreshes the channel's authorisation before reading anything, so a revoked authorisation stops that access at once.

Everything else - the operator's own scripts, audio, images and finished videos - is the operator's own content and stays until they delete it.

Deleting everything, on request

ytpipe carries the command that does it. ytpipe delete-data lists every stored thing - the local database, the artifacts directories and the secrets directory - and ytpipe delete-data --yes deletes all of it immediately, rather than within the 7 calendar days the YouTube API Services Developer Policies allow (section III.E.4.g). Nothing is kept back and nothing is copied elsewhere first.

Deleting the data stored by ytpipe does not, in any way, affect data stored by YouTube. To delete data on YouTube - your videos, their metadata, your channel - use a YouTube Application (youtube.com or the YouTube app) or an authorized API Client that supports deleting that data.

Withdrawing the authorisation

There are two ways, and both end with the stored data gone.

  • ytpipe revoke --channel <name> --yes tells Google the consent is withdrawn, by posting the token to Google's revocation endpoint, and then deletes that channel's stored YouTube API data and the token itself. That is immediate, not within the 7 calendar days section III.D.2.c.i allows.
  • The Google security settings page at security.google.com/settings/security/permissions (also reachable at myaccount.google.com/permissions) withdraws it from Google's side, and the stored token stops working at once. ytpipe checks every token on every run and whenever ytpipe authorization is run; a token Google will no longer refresh is treated as a withdrawn consent, and that channel's stored YouTube API data is deleted then and there, rather than within the 30 calendar days section III.D.2.c.ii allows.
